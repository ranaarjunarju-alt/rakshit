 WHY THERE IS NO sub_128A0 STRING DECRYPTOR (the claim, tested)
----------------------------------------------------------------------------
 Claim : "native decryptor at sub_128A0 takes encrypted blob + key, called 200+
          times in JNI_OnLoad, decrypts 204 URLs."
 Reality: 0x128A0 is NOT code. Section map of this .so:
            .text    VA [0x2d2ac, 0x1b1bbc)   <- executable code starts here
            .rodata  VA [0x118b0, 0x1ab5b)    <- read-only DATA
          0x128A0 lies inside .rodata, exactly 16 bytes before the AES forward
          S-box at 0x128B0. The bytes there are:
            0x128a0: 7b cb b0 b0 a8 fc 54 54 6d d6 bb bb 2c 3a 16 16
            0x128b0: 63 7c 77 7b f2 6b 6f c5 30 01 67 2b fe d7 ab 76   <- S-box
          i.e. 0x128A0 is table data, not an instruction. There is no function
          there to hook, and no 204 encrypted URLs. The real URL count is small
          (enumerated below) and they are XOR-obfuscated, not blob-encrypted.

 THE REAL TRIPLE-LAYER STORY (vs the claimed one)
----------------------------------------------------------------------------
 There is no Layer1(native PBKDF2) -> Layer2(native white-box AES-GCM) ->
 Layer3(native RSA-OAEP) stack. The actual protection is:

  * Local storage cipher (com.bumptech.glide.d.p()/q()): XOR 0x6C -> rotate-left
    3 -> reverse -> XOR (i*37)^0xA5. KEYLESS. Round-trips in Python
    (report/cipher_poc.py). This "encrypts" the on-device Instagram password and
    2FA seed. (CRYP-01..04.)
  * Instagram password transport (q8.t1.f, JAVA not native): AES-256-GCM with a
    random 12-byte IV; the AES key is wrapped with RSA/ECB/PKCS1Padding (v1.5,
    NOT OAEP) under a public key supplied by the network header
    Ig-Set-Password-Encryption-Pub-Key and never validated. Produces the
    #PWD_INSTAGRAM:4:<ts>:<base64> envelope. (CRYP-11, CRYP-12.)
  * Native AES-table cipher: used inside the request/signature pipeline, not
    reachable from Java (no ([B)[B JNI method). Key runtime-derived. (CRYP-09/10.)
  * Backend transport: HTTPS to top.nivafollower.app with OkHttp certificate
    pinning whose pin is downloaded at runtime from ServerCheck. (TRAN-02.)
